# ระบบอัปเดต All for Cabal — ข้อตกลงระหว่างออกแบบ

สถานะ: ตอบครบ Q1–Q8 แล้ว รอยืนยันสรุปความเข้าใจร่วมกันก่อนเริ่ม implementation

## ข้อตกลงที่ยืนยันแล้ว

- Q1: รุ่นแรกดาวน์โหลด Setup เต็มผ่านโปรแกรมและติดตั้งให้ ไม่ทำแพตช์เฉพาะไฟล์ที่เปลี่ยน ผู้ใช้ไม่ต้องไปดาวน์โหลด Setup เอง
- Q2: ผู้ใช้กดเริ่มอัปเดตเอง
- Q3: เลื่อนอัปเดตหรือเชื่อมต่อไม่ได้ก็ยังใช้รุ่นเดิมต่อได้
- Q4: แสดงรายละเอียดเวอร์ชันเป็น popup และมีปุ่มเปิดดูซ้ำ ไม่ได้ขอหน้าประวัติแยก
- Q5: ตรวจตอนเปิดโปรแกรม แสดง popup อัตโนมัติครั้งเดียวต่อเวอร์ชันใหม่ มีปุ่มดูซ้ำและตรวจอัปเดตเอง
- Q6: ถ้ามีงานกำลังทำ ให้แจ้งรอจนเสร็จและให้ผู้ใช้กดอัปเดตอีกครั้ง ไม่ปิดงานกลางทางหรือเริ่มติดตั้งอัตโนมัติเมื่อคิวจบ
- Q7: เก็บร่างและคิวที่ยังไม่ได้สร้างไว้ทำต่อหลังอัปเดต เตือนก่อนหากมีไฟล์ที่เลือกแต่ยังไม่ได้ Import ซึ่งอาจต้องเลือกใหม่ หรือมีหน้า Aztek ที่กรอกค้างอยู่
- Q8: หากติดตั้งไม่สำเร็จ แสดงสาเหตุและปุ่มลองใหม่ เก็บข้อมูลเดิมไว้ รุ่นแรกไม่มีการย้อนเวอร์ชันอัตโนมัติ

## ลำดับการใช้งานที่เสนอให้ยืนยันรวม

เปิดโปรแกรม → ตรวจเวอร์ชัน → แสดงรายละเอียดเวอร์ชันใหม่ → ผู้ใช้กดอัปเดตเมื่อพร้อม → ตรวจงานและร่างที่ค้าง → ดาวน์โหลดและตรวจไฟล์ Setup → ปิดโปรแกรมเพื่อติดตั้ง → เปิดโปรแกรมกลับมา

ดาวน์โหลดหรือเช็กอัปเดตไม่ได้ยังใช้รุ่นเดิมต่อได้ ส่วนการติดตั้งที่ล้มเหลวต้องแสดงผลตามจริง ไม่รับประกันว่ารุ่นเดิมยังเปิดได้หลังมีการแทนที่ไฟล์บางส่วน

## ขอบเขตของเอกสาร

บันทึกพฤติกรรมที่ผู้ใช้เลือก ยังไม่ใช่รายละเอียด implementation หรือผลการทดสอบ และยังไม่มีการแก้โค้ดระบบอัปเดตจากการสัมภาษณ์นี้

## ข้อเท็จจริงจากโค้ดปัจจุบัน

- ตัว Launcher ยังไม่มีระบบอัปเดต ต้องติดตั้งรุ่นที่รองรับระบบนี้ก่อนหนึ่งครั้ง
- Setup เดิมติดตั้งทับด้วย AppId คงเดิมและแยกข้อมูลผู้ใช้ออกจากไฟล์โปรแกรม
- silent install ปัจจุบันไม่เปิดโปรแกรมกลับเอง ต้องเพิ่มขั้นตอนเปิดใหม่
- ยังไม่มีตัวกั้นงานใหม่ร่วมกับการรอให้งาน Aztek จบก่อนติดตั้ง
- ข้อมูลร่างบางหน้าอยู่ใน browser storage การสำรองฐานข้อมูลอย่างเดียวไม่ครอบคลุมร่างเหล่านั้น
