# 01: ตรวจเวอร์ชันและแสดง Update Details Popup

ดำเนินการใน Local checkout แล้ว; หลักฐาน: `docs/verification/2026-09-14-local-auto-update.md`

## What to build

เมื่อเปิด All for Cabal Local ให้ตรวจ Release เบื้องหลังโดยไม่ขวางการใช้งาน แสดงเวอร์ชันปัจจุบัน รุ่นใหม่ และสิ่งที่เปลี่ยนเป็น Update Details Popup บนหน้าเครื่องมือ มีปุ่มไว้ก่อน เปิดดูซ้ำ และตรวจอัปเดตเอง การเปิดหลายแท็บหรือโปรแกรมซ้ำไม่ทำให้ popup เด้งซ้ำสำหรับรุ่นที่เคยแสดงแล้ว

ใช้ Release เสถียรของ `momozxmo/tool-cabal-local` และเริ่มสถานะอัปเดตร่วมที่ runtime เป็นเจ้าของ เพื่อให้งานดาวน์โหลดกับงานเตรียมติดตั้งใช้ต่อได้ ใช้เวอร์ชันเดียวกันใน build, Setup และ runtime ไม่เพิ่มบริการกลางใหม่

## Acceptance criteria

- [ ] โปรแกรมที่ build แล้วแสดงเวอร์ชันจริงตรงกับ Setup และสถานะ Local ไม่ใช้เลขเวอร์ชันของ Release ล่าสุดแทนเวอร์ชันที่ติดตั้ง
- [ ] ตรวจตอนเปิด Local runtime และจากปุ่มตรวจเองได้ การเปิดแท็บเพิ่มไม่เริ่มตรวจเบื้องหลังซ้ำโดยไม่จำเป็น
- [ ] เลือกเฉพาะรุ่นเสถียรที่ใหม่กว่า ไม่รวม draft/prerelease/รุ่นเดิม/รุ่นเก่า และเรียง 0.1.9 กับ 0.1.30 ได้ถูกต้อง
- [ ] หน้า Item Finder, Bundle, Item Code, Event และ Product แสดง popup ร่วมพร้อมรุ่นและรายการแก้ไขเป็นภาษาไทย
- [ ] Popup อัตโนมัติแสดงครั้งเดียวต่อเวอร์ชันต่อข้อมูล Local ของผู้ใช้ Windows ข้ามหน้า แท็บ และการเปิดโปรแกรมใหม่ โดยบันทึกเมื่อแสดงจริง
- [ ] ผู้ใช้ปิด popup แล้วทำงานต่อได้ มีปุ่มดูซ้ำและตรวจเอง ไม่มีหน้าประวัติแยก
- [ ] Release notes ไม่สามารถรัน HTML หรือสคริปต์ที่เป็นอันตรายได้
- [ ] ไม่มีอัปเดตหรือเครือข่ายขัดข้องไม่ขวางการใช้งาน เมื่อกดตรวจเองเห็นผลหรือข้อความให้ลองใหม่ได้
- [ ] ยังไม่เปิดเส้นทางเรียก Setup ในงานนี้ ปุ่มดาวน์โหลด/ติดตั้งจะใช้งานจริงเมื่อส่วนที่เกี่ยวข้องพร้อม ไม่แสดงผลสำเร็จหลอก
- [ ] ทดสอบ UI/Local workflow และหลายแท็บจริง โดยจำลองแหล่ง Release ที่ขอบระบบ รวมเวอร์ชันผิดรูปแบบ notes อันตราย และกรณี offline

## Blocked by

None (can start immediately).
