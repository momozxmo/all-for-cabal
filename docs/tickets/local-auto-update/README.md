# งานย่อย All for Cabal Update

สถานะ: ดำเนินการทั้ง 4 งานตามคำสั่ง `implement` แล้วใน Local checkout ยังไม่เผยแพร่ GitHub Issues หรือ Release โปรแกรม ดูผลตรวจใน `docs/verification/2026-09-14-local-auto-update.md`

ต้นทาง: สเปก All for Cabal Update — อัปเดตผ่านโปรแกรมพร้อมรายละเอียดเวอร์ชัน และข้อตกลง Q1–Q8

| งาน | ผลที่ใช้งาน/ทดสอบได้ | รอ |
| --- | --- | --- |
| [01](./01-update-details-popup.md) | ตรวจเวอร์ชันและแสดง Update Details Popup พร้อมเปิดดูซ้ำ | ไม่มี |
| [02](./02-download-verified-setup.md) | กดดาวน์โหลด Setup เห็นความคืบหน้า ตรวจไฟล์ และลองใหม่ | 01 |
| [03](./03-preserve-work-before-update.md) | เตรียมติดตั้งโดยกั้นงานที่กำลังทำ เก็บร่าง/คิว และเตือนสิ่งที่ค้าง | 01 |
| [04](./04-install-restart-and-retry.md) | เชื่อมไฟล์พร้อมและการเตรียมพร้อมเข้ากับการติดตั้งจริง เปิดกลับ และ retry | 02, 03 |

02 และ 03 ใช้สถานะอัปเดตร่วมที่เริ่มใน 01 แต่ไม่จำเป็นต้องรอกัน 04 รวมผลทั้งสองงานก่อนอนุญาตให้เรียก Setup จริง

ทุกงานมีเกณฑ์ตรวจรับและทดสอบพฤติกรรมตั้งแต่ UI/Local API ผ่านระบบจริง โดยแทนเฉพาะเครือข่ายและการเรียก installer ระหว่าง automated tests ไม่มีงานแยกตามชั้น backend/frontend และไม่ต้องมีงาน refactor กว้างก่อนเริ่ม การปรับจุดเชื่อมที่จำเป็นอยู่ในงานที่ใช้มัน

## การเผยแพร่เมื่ออนุมัติ

สร้าง 4 Issues ใน `momozxmo/all-for-cabal` ตามลำดับ พร้อม `ready-for-agent` และความสัมพันธ์ blocking ด้วยเลข issue จริง ใช้ native dependency หากใช้ได้ มิฉะนั้นระบุใน Blocked by ไม่สร้างหรือแก้ Release โปรแกรมจากขั้นแตกงานนี้

สเปกต้นทางยังเป็นเอกสาร Local และยังไม่มี parent issue ที่ยืนยันไว้ จึงไม่สมมติเลข parent และไม่สร้าง parent ซ้ำโดยไม่ตรวจสอบ
