# 03: เตรียมอัปเดตโดยรักษางาน ร่าง และคิวทุกหน้า

ดำเนินการใน Local checkout แล้ว; หลักฐาน: `docs/verification/2026-09-14-local-auto-update.md`

## What to build

เมื่อผู้ใช้ขออัปเดต ให้แสดงว่าพร้อมหรือมีงานต้องจัดการก่อน หากกำลังค้นหา สร้างข้อมูล preview เชื่อม Aztek หรือรันทุกอันในคิว ให้รอจนจบแล้วกดใหม่ หากไม่มีงานให้เก็บร่างจากทุกหน้าและทุกแท็บ พร้อมเตือนไฟล์/รูปที่ยังไม่เก็บถาวรและหน้า Aztek ที่กรอกค้างก่อนอนุญาตให้ติดตั้ง

ต่อจากสถานะร่วมในงาน 01 เพิ่มการประสานช่วงเตรียมติดตั้งกับจุดควบคุมงาน Browser และกลไกเก็บ workspace เดิม ให้ตรวจว่าว่างกับกั้นงานใหม่ได้โดยไม่มีงานแทรก ระหว่างทดสอบจบที่พร้อมส่งต่อให้ installer จำลอง ไม่ต้องรอการดาวน์โหลดจริงจากงาน 02

## Acceptance criteria

- [ ] งานกำลังทำและงานรอทำทุก workflow รวมการรันทั้งคิว ทำให้ขออัปเดตแล้วได้รับข้อความรอ ไม่ปิด process หรือกดบันทึก Aztek แทนผู้ใช้
- [ ] คิวร่างที่ยังไม่รันไม่ถูกนับเป็นงานกำลังทำ หลังงานจบไม่มีการติดตั้งอัตโนมัติ ต้องกดใหม่
- [ ] การเริ่มงานกับการเตรียมติดตั้งพร้อมกันไม่ผ่านทั้งคู่: ถ้างานเริ่มก่อนให้อัปเดตรอ ถ้าเตรียมปิดก่อนให้งานใหม่ถูกปฏิเสธอย่างเข้าใจได้
- [ ] ทะเบียนแท็บ/สถานะร่วมครอบคลุมแท็บที่กำลังแก้ไขทุกหน้า และกั้นการแก้ร่าง/รับงานใหม่เฉพาะช่วงเตรียมติดตั้ง
- [ ] เก็บและคืนค่าร่างที่แก้เอง รายการ/ลำดับคิว และสถานะสร้างสำเร็จของ Item Finder, Bundle, Item Code, Event และ Product โดยใช้กลไกเดิม ไม่สร้างระบบเก็บงานซ้ำอีกชุด
- [ ] เก็บร่างล้มเหลวหรือแท็บที่กำลังแก้ไขไม่ตอบรับ ต้องไม่ผ่านเป็นพร้อมติดตั้ง แสดงสิ่งที่ต้องจัดการ และปลดการกั้นเมื่อยกเลิก/ล้มเหลว
- [ ] ไฟล์ที่เลือกแต่ยังไม่ Import และรูป/ไฟล์แนบในหน่วยความจำมีคำเตือนเจาะจง ให้กลับไปจัดการหรือยอมรับว่าต้องเลือกใหม่ได้ ไม่อ้างว่าเก็บไฟล์แล้วเพราะยังมีชื่อไฟล์
- [ ] เตือนเมื่อมีหน้า Aztek/preview ที่โปรแกรมดูแลค้างอยู่ และไม่ปิด browser ที่ไม่เกี่ยวข้อง ไม่สร้างข้อมูลจริงระหว่างเตรียมติดตั้ง
- [ ] เปิดกลับบน Local origin เดิมแล้วร่าง/คิวยังอยู่ ไม่เริ่มส่งสร้างเองหรือส่งรายการที่สำเร็จแล้วซ้ำ
- [ ] การขอเตรียมพร้อมซ้ำจากหลายแท็บไม่สร้างขั้นปิดหลายชุด มีการตรวจความพร้อมครั้งใหม่ก่อนติดตั้งจริง ไม่ใช้ผลว่าว่างเก่าเป็นสิทธิ์ติดตั้งถาวร
- [ ] ทดสอบผ่าน UI/Local workflow ด้วยงานจำลองที่ควบคุมจังหวะได้ รวมการรันทั้งคิว race หลายแท็บ การเก็บร่างพลาด และ reload เพื่อยืนยันข้อมูลที่คืนมาจริง
