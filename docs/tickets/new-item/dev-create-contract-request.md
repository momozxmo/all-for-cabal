## ข้อความคำขอเดิมก่อนรับ source/receipt — ประวัติเท่านั้น

ขอข้อมูลขั้นบันทึก Item ใหม่ของ CabalPC TH / CabalPC SEA / CabalM TH / CabalM SEA เพื่อเชื่อม Tools ให้ถูกต้องและป้องกันการสร้างซ้ำเมื่อการเชื่อมต่อหลุดครับ

ส่ง **โค้ดที่ใช้บันทึกพร้อม API client/schema ที่เรียกต่อ** หรือ **ตัวอย่าง request/response เดิมที่ลบข้อมูลลับแล้ว** ก็ได้ ไม่ต้องทดลองสร้างข้อมูลจริงเพื่อเก็บหลักฐานใหม่

สิ่งที่ต้องทราบ:

1. **บันทึกที่ไหนและส่งค่าอะไร** — HTTP method, API host/path, ชื่อ field/type/ค่าที่รับของ Name, Kind, Option, Duration, Type, Tradeable, Description, display-on-web และรูปที่ไม่บังคับแนบ รวมถึงค่าที่ต่างกันระหว่างสี่เกม หากใช้ contract เดียวกันช่วยยืนยันเกมที่ใช้ร่วมกันได้ ไม่อนุมานเองจากชื่อ field บนฟอร์ม
2. **ยืนยันว่าสำเร็จและรับ Item ID อย่างไร** — status/body ของคำตอบสำเร็จ ตำแหน่ง Item ID ของรายการที่เพิ่งสร้าง วิธีผูกคำตอบกับคำขอ/เกมนั้น และตัวอย่างคำตอบผิดพลาด/ข้อมูลซ้ำถ้ามี ต้องไม่สับสนกับ ID ของข้อมูลอื่นที่ซ้อนอยู่ในคำตอบ
3. **ผู้ใช้ยืนยันก่อนส่งบันทึกตรงไหน** — กดสร้างแล้วส่งทันทีหรือมี dialog; ถ้ามี ขอ control/HTML ที่ใช้ยืนยันและยกเลิก พร้อม stable IDs หากไม่มี dialog ให้ยืนยันว่าไม่มี ไม่ต้องสร้าง dialog สมมติให้ Tools
4. **กรณีไม่รับคำตอบหลังส่งไปแล้ว** — มีวิธีตรวจสถานะคำขอหรือป้องกันการสร้างซ้ำที่ server รองรับจริงหรือไม่ ถ้ามีขอวิธีและขอบเขต; ถ้าไม่มีให้ระบุว่าไม่มี Tools จะรักษา Unconfirmed และไม่ส่งซ้ำเอง

สำหรับรูป ขอวิธีส่งไฟล์/ค่าอ้างอิงและการตอบกลับที่ใช้จริงด้วย ไม่ถือว่ากติกาตรวจรูปในเครื่องของ Tools เป็นกติกาของ Aztek server

## ส่งอะไรได้บ้าง

- Source ของ handler บันทึก, API client ที่ handler เรียก และ schema/DTO ที่เกี่ยวข้อง จะช่วยยืนยันได้โดยไม่บันทึกข้อมูลจริง
- หรือ request/response เดิมแบบแยกเฉพาะส่วนที่จำเป็น โดยคงชื่อ field/type/โครงสร้างและความสัมพันธ์ของ ID แต่แทนค่าระเบียนด้วยข้อมูลสังเคราะห์ที่สอดคล้องกัน
- ระบุเกม/page/state และรุ่นโค้ดหรือวันที่ของหลักฐาน เพื่อไม่ใช้ contract เก่าหรือของ Item Code แทน Item

ไม่ส่ง cookie, Authorization, token, session/storage state, private key, URL ที่มีข้อมูลลับ หรือ HAR ทั้งชุด ไม่ต้องให้สิทธิ์บัญชีแก่ Tools/เอเจนต์เพิ่มเพื่อส่งหลักฐานนี้

## หลักฐาน ณ เวลาร่างบรีฟเดิม — ถูกเพิ่มเติมภายหลังตาม frontend contract

- เคยพบชื่อ asset `CreateItemPage-C4mRAgrA.js`, `getItemDetail-BA85naCz.js`, `item.schema-C49_RdMf.js` แต่ **ยังไม่ได้อ่าน source ที่ยืนยัน contract** ชื่อไฟล์เหล่านี้ไม่ใช่หลักฐาน endpoint/schema และอาจเปลี่ยนตาม build ส่ง source รุ่นปัจจุบันแทนได้
- ผลค้นหา Item เดิมหรือการพบ Item ที่มีชื่อ/สามค่าเดียวกัน ไม่พิสูจน์ว่าคำขอสร้างที่ค้างเป็นผู้สร้างรายการนั้น จึงยังไม่ใช้ปลด Unconfirmed

## ลำดับงานที่วางไว้ในบรีฟเดิม — ไม่ใช่คำสั่งให้เริ่มหรือรีวิวซ้ำ

ตรวจ contract แยกตามเกม → เขียน integration tests ให้เห็น RED → ต่อ checkpoint ก่อนส่งบันทึก/รับ ID/ตรวจข้อมูลจริง → ทดสอบคิวหยุดและกรณีหลุดโดยไม่สร้างซ้ำ → ต่อการกู้สถานะที่มีหลักฐานพอ → final full และ fresh review

ไม่เปิดสร้างจริง ไม่เดา endpoint/response และไม่ปิด #12 จากผลจำลอง การทดสอบกับระบบจริง, commit/push, Setup/release และปิด issue ยังต้องอยู่ภายใต้สิทธิ์แยกที่เกี่ยวข้อง
