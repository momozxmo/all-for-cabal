# ส่วนสร้าง CabalM TH — สถานะในเครื่อง

สถานะปัจจุบัน27ตุลาคม2026: ยังไม่ครบ #12 และยังไม่มี Setup รุ่นที่รวมงานนี้. ส่วนที่รองรับใน working tree รวมการรวมร่างหลังแก้ข้อมูลและการเปิดรายละเอียดประวัติย้อนหลัง ผ่าน FULL4 3053กรณี/คำเตือนเดิม1รายการแล้ว. สร้างใหม่ได้เฉพาะ CabalM TH; อีกสามเกมและการยืนยันรายการเมื่อคำตอบหายจนไม่มีIDยังปิดอยู่. ดู [เกณฑ์ปัจจุบัน](acceptance-current.md) และ [ผลรอบเต็ม](coverage.md)

เนื้อหาตั้งแต่หัวข้อถัดไปเป็นประวัติการพัฒนาส่วน MTH ณ26ตุลาคมและก่อนเพิ่มส่วนรวมร่าง ไม่ใช้ข้อความ “ยังไม่รองรับ/ยังไม่full/review” ด้านล่างเป็นสถานะปัจจุบัน และไม่ต้องรันทดสอบเก่าซ้ำ

## ทำเพิ่มแล้ว

API `/api/new-items/run` รับเฉพาะร่างที่ยืนยันแล้ว พร้อม ID/revision/เกมและคำตัดสิน `create_new` ของแต่ละรายการ ไม่รับผลผ่านหรือข้อมูลอ่านกลับที่ผู้เรียกแต่งเอง

Baselineหลังreviewก่อนเพิ่มส่วนรวมร่าง27ตุลาคม: ต้องค้นItemเดิมก่อนและส่ง `search_id` ของผลค้นที่ผูกowner/เกม/revision/frozenpayloadตรงกัน. ตอนนั้นscopeที่finalpayloadซ้ำจะถูกปฏิเสธก่อนbrowser. ต่อมาเพิ่ม explicit `group_identical=true` หลังผู้ใช้เลือกยืนยันแล้ว: ค่าที่ใช้สร้างทุกช่อง/เกม/ภาพต้องตรงกัน จึงสร้างร่วมกันและเก็บผลเทียบแต่ละต้นฉบับแยกกัน; callerเดิมที่ไม่opt-inยังปฏิเสธscopeซ้ำ. ส่วนนี้ผ่านfull3และยังอยู่ครบในfull4แล้ว ไม่ใช่ข้อจำกัดปัจจุบัน. ผล475ด้านล่างเป็นmilestoneก่อนreviewfix ไม่ใช่finalfullของsourceปัจจุบัน

ทางเดินที่ตรวจด้วยเว็บจำลอง:

1. ตรวจสิทธิ์ เกม revision และรูปของทุกรายการก่อนเปิด browser แล้วตรวจใหม่หลังรอคิว
2. กรอกฟอร์มด้วย ID ที่พิสูจน์ไว้ อ่านค่ากลับ และเปิดกล่องยืนยันที่ตรงกับ Item
3. ก่อนปล่อย POST ออก บันทึกสถานะ “กำลังส่ง” ลงฐานข้อมูลให้เสร็จก่อน อนุญาตเพียงคำขอเดียวที่ตรงปลายทาง/ฟอร์ม/ค่าของร่าง
4. รับ ID จาก `data.data.id` ของคำตอบคำขอนั้นเท่านั้น ตรวจเกม แล้วบันทึก ID ทันที ก่อนเปิดหน้าอ่านกลับ
5. อ่าน Item ใหม่เพื่อเทียบต้นฉบับ ไปต่อเฉพาะผ่านและข้อมูลครบ ถ้าไม่ตรงหรืออ่านไม่ครบ ให้หยุดและเก็บ ID ไว้

ถ้าส่งแล้วแต่ไม่ได้คำตอบที่ยืนยันได้ จะเป็น “ยังยืนยันผลสร้างไม่ได้” ไม่กลับเป็นร่างพร้อมสร้าง และไม่ส่งซ้ำเอง การกด API ซ้ำหรือคำขอจากหน้าเว็บที่พยายามส่งอีกครั้งต้องไม่เพิ่ม POST ที่ปล่อยออก

รูปมาจากไฟล์ส่วนตัวที่ผูกกับร่างและตรวจ hash แล้ว ส่ง bytes เดียวกันในช่องภาพไทย/อังกฤษของ POST เดียว ไม่แยกอัปโหลดก่อนยืนยัน รูปที่อ่านกลับตรวจเพียงว่ามีอยู่ ไม่อ้างพิสูจน์เนื้อภาพตรงกัน

## การเลือกและยืนยันบนหน้าจอ

หลังยืนยันร่างแล้ว ผู้ใช้ต้องติ๊ก “เลือกสร้างใหม่” เอง ไม่มีเลือกให้อัตโนมัติ กล่องยืนยันแสดงเกม จำนวน ชื่อ Kind/Option/Duration/Type/Tradeable รูปและคำอธิบาย ยกเลิก/Escape ไม่ส่งและคืน focus ให้ปุ่มเดิม

ขณะส่งล็อกcontrolsที่ขัดกันและบอกให้รอ หากคำตอบของToolsหาย แสดงให้ตรวจประวัติ/อย่าสร้างซ้ำ ไม่แนะนำลองสร้างใหม่ ปุ่มโหลดประวัติและการเปิดหน้าใหม่อ่านสถานะเท่านั้น

หากมีผลผิด/ไม่ครบ/unconfirmed ของผู้ใช้ในเกมนี้ ต้องรับทราบผลล่าสุดก่อนเลือกชุดใหม่ APIตรวจซ้ำหลังรอgateด้วย การรับทราบไม่เริ่มงานเอง ไม่แก้ผลเดิมเป็นผ่าน และไม่ปลดรายการเดิมให้สร้างซ้ำ เหลือรายการconfirmedให้เลือกเองใหม่ จึงไม่ลากรายการที่ไม่ได้เลือกไปทำต่อ

## ขอบเขตที่ยังไม่เปิด

- ใช้ positive response/UUID ของ CabalM TH เท่านั้น อีกสามเกมปฏิเสธการสร้างก่อนเปิด browser
- ตัวจับคำขอรองรับ multipart ชุดฟิลด์ที่พิสูจน์แล้ว: GENERAL, ไม่แสดงเว็บ, stackable=false และรูปไม่บังคับ ฟิลด์เพิ่มเติมหรือรูปแบบอื่นหยุด ไม่เดาค่า
- หน้าที่ต้องใช้คำขออื่นนอก allowlist จะหยุดอย่างปลอดภัย ไม่ขยาย allowlist หรือทดลองกับเว็บจริงเอง
- ยังไม่มีหลักฐานที่ผูกงานคำตอบหายกับ Item ที่สร้างจริงเพื่อ Resolve อย่างแน่นอน การพบชื่อ/สามค่าตรงกันไม่พอให้ประกาศว่าสร้างโดยคำขอเดิม
- UIสร้าง/เลือกชุดใหม่หลังรับทราบรองรับ MTH ในรุ่นพัฒนาเท่านั้น ยังไม่ใช่ทั้งสี่เกม/positiveResolve/finalfull/freshreview จึงยังไม่แพ็กSetupหรือปิด #12
